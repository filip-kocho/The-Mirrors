# Architecture

- **Learning and ownership:** `systems/spells.ts` validates exact Element IDs and Tool access before the reducer spends anything; `spentElements` preserves the 70-token economy. `hero.spellSlots` maps four permanent Knowledge markers to actual Spell tokens in inventory. `systems/knowledge.ts` checks all four achievements. Newly discovered Companions go to `hero.companions` and move with their owner; private Secrets stay in `hero.secrets`. Death and voluntary Spell departures clear the corresponding equipped slots.
- **Artwork:** original designer PNG sheets are bundled locally in `public/icons/`. SVG viewports in `iconAtlas.ts` render the individual symbols at inventory, card, castle, and Kaleidoscope sizes. No remote service is used during play.

- **Next.js App Router / React / strict TypeScript:** local client game at `/` and `/game`. No runtime network dependencies.
- **Pure domain engine:** `src/game/domain/engine.ts` contains schemas, initial state, commands, immutable reducer, conservation checks and public room projection. A rejected command never mutates its input. Events use monotonic IDs and turn numbers, not clocks.
- **Reproducible setup:** new games use browser `crypto.randomUUID()` at the store boundary; explicit seeds and saves retain reproducibility. The engine uses a string-seeded PRNG and Fisher–Yates shuffles; every pool is allocated before exploration. Room `findings` is the immutable original allocation; `objects` is the live inventory only after reveal. Never sum both as active supply.
- **Physical integrity:** portable mirrors plus installed pairs plus removed collided pairs remain the same 70 instances. Elements remain 70 physical IDs. Discoveries come from seeded decks. Sigils currently use a color ledger backed by unique room restorations; explicit token IDs and binding states belong to the unfinished Spell phase.
- **Source data:** original catalog JSON imported directly; the user-supplied v0.4 module overlays its 35 Black Mirror definitions by stable ID. Zod validates every card and mathematical assertions fail startup on changed economies. `cardEffects.ts` gives every ID an explicit adapter entry: discovery, capacity, typed Black Mirror curse, or unimplemented text. No runtime parsing of English effect strings.
- **Rules:** validated GameRulesConfig is copied into each state/save. Edit defaults in `gameRulesConfig.ts` and revenge values in JSON for new playtests. Saved rules persist except explicit designer-rule migrations. UI variant editing is not yet exposed.
- **Map graph:** 36 nodes in five wings, reference-matched corridors, stable IDs, coordinates and rotation. Breadth-first path preview; reducer independently verifies the submitted path. The Kaleidoscope uses 35 traced pentagons with a separate authoritative shared-edge graph. See DESIGN_REFERENCES.md for source and saved-game handling.
- **State/UI boundary:** Zustand wraps commands and local persistence. Components derive previews and never mutate authoritative state. `CardFace` renders the family-specific card anatomy, `PlayerSigils` shows collected Sigils above Knowledge, `PlayerCollection` shows Companions/Secrets, and `SpellAction` embeds Learn/Leave icons in cards and room tokens. `automaticLearningPlan` selects exact payment and the first free unlocked slot in both UI eligibility and the reducer. `SignaturePanel` now renders only the endgame; `PenaltyDialog` starts the typed curse queue; `CurseChoiceDialog` presents serialized validated choices and map targets. `CastleBoard` renders square rooms and the Hall portal; `KaleidoscopeBoard` renders the zoomed puzzle, legal placements and bonus preview. The main `Game` component renders lobby, character board, castle, inspectors and privacy. Its two-column table places the inspector above the map and Occuldor/chronicle below; End Turn lives on the character board. The final-room Confront action remains in the Occuldor panel.
- **Visibility and privacy:** drawn White and Black Mirrors stay as icons in carried and room lists, including paired Mirrors. Clicking either discovered Mirror opens its oval card face; physical flipping/curse activation remains restricted to Collide. Secrets appear as anonymous icons only on the active owner?s character board; clicking reveals one card. Closed dialogs do not mount catalog or private card text. All explored room objects are publicly inspectable, even from elsewhere. Undiscovered room contents and undealt cards remain hidden. A pass screen unmounts the table and resets private Secret reveal state. Browser saves remain inspectable through developer tools; this is a trusted local hot-seat model.
- **Mirror placement:** the character board opens a chooser for one White and one Black Mirror from the active hero's hand and current room. The typed `PLACE_MIRRORS` command includes both physical IDs. `COLLIDE` now means flipping an unblocked placed Black Mirror in the active hero?s room. The reducer validates both choices before consuming either, activates the selected White's exact slots, and retains the selected Black for its later flip. Cancellation changes no game state. Existing saves retain the `installed` turn flag for compatibility.
- **Persistence:** save key `the-mirrors-save-v1`; schemas validate and supply checks run on load. New fields have migration defaults: empty Companion lists, four null Spell slots and an empty spent-Element pool. Rules revision 3 preserves the revision-2 Knowledge migration and removes the default per-turn pair/flip cap. Old pending manual curses are migrated atomically to awarded Sigil/Rage and a pending penalty popup, consuming their installed pair exactly once. Unknown versions are rejected.
- **Resolution:** COLLIDE reveals a Black Mirror without awarding rewards. CONTINUE_COLLISION begins immediate effects; CURSE_CHOICE resumes a saved queue. When complete, commit restoration/Sigil/Rage once. PLACE commits the pentagon and Courage, then runs deferred effects. Save/load preserves each intermediate choice. Death cannot interrupt a legally started restoration. See BLACK_MIRROR_IMPLEMENTATION.md.
- **Ability limits:** all Black Mirror effects have typed operations. Printed Spell effects and remaining Companion powers remain unavailable; revised Item effects and v0.5 Secret achievements are executable; no effect is claimed from prose alone. Sigil Seal suppression predicates and binding preservation exist independently of future casting commands. Historical manualNotes remain only for save compatibility.

Tests cover source economies, reproducible setup, navigation, privacy, transfers, collision ordering, conservation, placement, full-board endgame and save/load. React Testing Library covers private Secrets, curse confirmation and reward preview. Playwright covers initial exploration/resume and the signature loop through a late-game victory fixture. Browser coverage includes Spell payment, equipped slots, automatic Companion ownership, private Secret clicks and resuming learned Spells.

Companion rendering: CompanionFigurine maps all ten stable catalog IDs to explicit pale SVG silhouettes. RoomParty derives follower placement directly from hero.companions and hero.room, so it requires no duplicate position state or save migration. Miniatures inherit room rotation and identify their holder through the base color and accessible label. TokenIcon reuses the same figurine for Companion inspection buttons.

Kaleidoscope legality is centralized in legalCell: an empty mosaic permits only outer-edge cells; a nonempty mosaic permits only empty cells sharing an edge with placed glass. Both highlighting and the PLACE command use this rule. The first placement depends on mosaic occupancy, not turn or player identity, and applies immediately on saved-game resume.

Placement scoring: placementBonuses lists every occupied shared-edge neighbor and its same/different-color contribution; placementReward adds them all plus one base Courage. The PLACE command accepts only a cell (no chosen neighbor) and recalculates scoring in the reducer. The puzzle highlights all contributing neighbors and previews the same sum. Saved mosaics require no migration; future placements use cumulative scoring without retroactive awards.

- Transfer controls use the pure `planTransfer` preview shared with the reducer, so carrying limits and room capacity bonuses match engine validation. `CardCatalog`, `HowToPlay` and `SpellCastGuide` separate collection browsing, instructions and printed casting references from the game table. The landing screen no longer exposes a seed field; explicit seeds remain available to the engine and tests.

Black Mirror architecture, token schema, topology overlays, validation, migration and extension examples: [BLACK_MIRROR_IMPLEMENTATION.md](BLACK_MIRROR_IMPLEMENTATION.md).

## Item v0.3 integration

Revised card IDs map to typed Item effects. itemAccess derives passive modifiers from carried plus current-room Items, deduplicated by card. elementPayment allocates actual tokens against discounted costs; itemActions produces validated Tool plans. USE_ITEM validates a complete selection and round/turn identity before paying costs. The immutable reducer persists the per-hero usage ledger and queues excess-capacity choices through the existing saved effect resolver. Central courage helpers distinguish penalties, voluntary costs and unpreventable losses. Permanent commitment is a separate BIND_SIGILS command; printed Spell casting remains unfinished. See ITEM_IMPLEMENTATION.md for the complete integration and review record.

Secret achievements: cards/secrets.ts supplies typed v0.5 definitions. systems/secrets.ts evaluates current holdings and validates claims; REVEAL_SECRET atomically moves the private card into completedSecrets and calls the existing Courage pipeline. Saved completed records contain ID, turn, reward, actual gain and optional tier. Public collections never expose private eligibility. See SECRET_IMPLEMENTATION.md.


## Spell activation and interface revision (2026-11-07)

Spell framework: spellState + sigils hold physical token identities, Quick assignments and lifecycle. spellActivation provides atomic validated CAST_SPELL; spellEffects declares per-ID adapters; spellModifiers supplies continuous hooks. Open-card socket selection is local React state until confirmation. Gem ownership is saved independently of mosaic colors.
